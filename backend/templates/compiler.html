How the terminal works

Run sends your program to this site's judge, which compiles it with the language's own toolchain (gcc, g++, javac, go, rustc, dotnet, tsc/Node, CPython, SQLite, Bash) inside the same isolation used for judged problems, feeds it your input, and returns stdout, stderr and the exit status. Nothing is simulated: if a language has no runtime on the host you are using, it is labelled “no runtime here” and Run stays disabled for it. On the static & mobile deployment there is no server judge, so real WebAssembly compilers and interpreters (Clang 22, OpenJDK + TeaVM, rustc, Roslyn, TypeScript 5.9, Go 1.24, Bash, SQLite, CPython 3.12, and isolated JavaScript) execute directly in Web Workers instead, and any unbundled runtime honestly reports “not run”. Want tests and a verdict instead of a bare terminal? Use the coding problems.
