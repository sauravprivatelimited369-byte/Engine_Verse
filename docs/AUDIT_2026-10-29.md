# Meridian — Audit round of 2026-10-29 (100-point product audit)

- **Date:** 2026-10-29
- **Repository:** `sauravprivatelimited369-byte/Engine_Verse`, branch `arena/f47b4c83-engine-verse`
- **Scope:** the audit's own top-ten priority list — academic correctness →
  reliable coding experience → trustworthy curricula → simplified first visit →
  progress portability → feature availability → search and navigation →
  personalisation → performance and accessibility → student-success
  measurement.
- **Method:** every change below is a repository change with a test that pins
  it. The audit distinguished confirmed published-page defects from risks that
  had never been tested; this document keeps that distinction. Where something
  is still unverified, it says so.

## 1. Academic correctness

### 1.1 Algorithm complexity was wrong in the published data — FIXED

**Was:** a confirmed defect. Thirteen problems in `seed_data/practice_data.py`
carried no complexity at all, and `scripts/seed.py` filled the gap with a
blanket `O(n)` / `O(n)` fallback. Binary Search — the algorithm most likely to
be looked up — was therefore published as **O(n) time, O(n) space** when the
correct answer is **O(log n) time, O(1) extra space**.

**Now:** `seed_data/complexity.py` is the single registry of complexity bounds
for all 105 problems. Both problem builders resolve through
`complexity.bounds(slug)`, and the seeder *refuses* to publish a problem with
no bounds rather than inventing one. `scripts/audit_complexity.py` audits the
corpus and exits non-zero on drift.

- `seed_data/complexity.py`, `seed_data/coding_common.py`,
  `seed_data/practice_data.py`, `scripts/seed.py`, `scripts/audit_complexity.py`
- `backend/tests/test_complexity_accuracy.py` — 33 tests, all passing.

### 1.2 The four reading depths were one document with four names — FIXED

**Was:** a confirmed defect. `DEPTHS["standard"]` contained `"simple"`, and
`section_body("simple", …)` was shared, so a beginner note and a standard note
on the same topic opened with identical text.

**Now:** the four depths are four different documents. `section_body(kind,
topic, slug, depth)` is depth-aware, `seed_notes()` passes the depth, and
`catalog.DEPTH_BLURB` describes each one. A note now carries exactly the
sections of its depth — that is the contract the tests enforce.

- `scripts/seed.py`, `backend/engineverse/catalog.py`
- `backend/tests/test_reading_depths.py`; the seed-coverage test now asserts
  the depth→sections contract instead of a fixed section count.

## 2. Reliable coding experience

### 2.1 "What runs here?" was answered three ways, and none was true — FIXED

**Was:** a confirmed defect. The compiler page said "Code execution is off",
the problem page said "Supported here: none — execution disabled", and the
homepage counted languages as though they all ran. None of the three was
derived from the deployment the reader was actually on.

**Now:** `backend/engineverse/execution.py` is the only place that answers it.
It reports, per language, whether this host runs it on the server judge, in
the browser, or not at all — and it distinguishes *running a program* from
*judging a problem*, because the browser runs one program with one stdin
while the hidden test cases and the verdict live on the server.

- `backend/engineverse/execution.py` (new)
- `backend/templates/compiler.html` — a "What runs here" table plus the
  three-way explainer.
- `backend/templates/problem.html`, `backend/templates/sheet.html`,
  `backend/templates/home.html` — all read the same table now.
- `backend/tests/test_audit_2026_10_29.py`.

### 2.2 A server deployment claimed the browser would run your code — FIXED

**Was:** a confirmed defect, found while fixing 2.1. `execution.py` assumed
that JavaScript "runs in your browser" on any deployment because a
pure-JavaScript engine needs no file. It does not: the worker that would run
it is constructed only on the static copy (`pages-live.js` and CodeLab's
static fallback), and a server deployment serves no `/runtimes/` directory.

The claim was also *cached*, so the static export's answer survived the export
and leaked onto the hosted app for the rest of the process.

**Now:** a server deployment reports no browser runtime at all, and the cache
is keyed on the deployment kind.

### 2.3 The static copy claimed every language compiled there — FIXED

**Was:** a confirmed defect. `pages-live.js` rewrote the compiler page's host
note to "Every language here compiles and executes right on your device",
which is only true of a copy that vendored every runtime. The copy's own
runtime manifest decides, and it now says so — naming the languages the copy
carries and stating that a language whose runtime files are missing is not
executed and is never marked as passed.

- `backend/static/js/pages-live.js`, `scripts/export_pages.py`.

## 3. Trustworthy curricula

### 3.1 Engineering Mathematics III was in the first-year catalogue — FIXED

**Was:** a confirmed defect. It is a third-year course.

**Now:** `seed_data/catalog.py` marks it `first_year = False`, and
`scripts/seed.py::validate_subject_catalogue()` refuses to publish a
first-year subject that sits outside year one, so the shelf cannot drift
back.

### 3.2 A subject page did not say which syllabus it came from — FIXED

**Now:** `catalog.subject_alignment()` returns the university, the
regulation/branch, the effective year, the semester and the credits, and the
subject page prints them in a "Syllabus alignment" table.

### 3.3 A draft note looked like a reviewed note — FIXED

**Was:** a confirmed defect. The warning badge appeared only for drafts, so
the *absence* of a warning read as "reviewed".

**Now:** every topic carries a badge — "Editorially reviewed" or "Public
learning draft" — with the date the note last changed.

## 9. Performance and accessibility

### 9.1 A formula is now spoken, not spelled — FIXED

**Was:** a confirmed defect. A rendered formula carried the raw LaTeX in its
accessible name (`aria-label="\sum_k I_k = 0"`), and a screen reader announces
that character by character: "backslash sum underscore k". The audit asked for
"proper ARIA labels or text alternatives"; the label existed, and it was not
readable.

**Now:** `markdown.tex_speech()` produces a spoken reading — "the sum of sub k
I sub k equals 0", "x divided by y", "the square root of 2" — and the exact
source stays on the element in `data-tex` for anyone who needs it.

- `backend/engineverse/markdown.py`, `backend/tests/test_markdown.py`.

### 9.2 A mastery percentage now says what it means — FIXED

**Was:** a confirmed defect. The dashboard printed "45%" with no indication of
whether that meant "nearly there" or "barely started".

**Now:** `progress.mastery_level()` gives every percentage a band ("Not
started", "Just started", "Getting there", "Nearly there", "Mastered") and a
line saying what moves it up. The bands match the thresholds
`update_topic_mastery` already uses, so the label can never contradict the
stored status.

### 9.3 A wrong answer has a way forward — FIXED

**Was:** a confirmed defect. The practice result page ended at "it has been
added to your mistake notebook", which is a record, not a route forward.

**Now:** a "What to do next" panel names the steps: read the explanation, read
the topic the question came from, try another question on the same topic, and
the mistake notebook. The result page also links to the rest of that topic's
questions.

### 9.4 Already in place and re-verified rather than changed

- `prefers-reduced-motion` is honoured by `scroll.js` (reveal, stagger and the
  counters all collapse to their final state) and by `engine3d.js` (the
  auto-spin is off when reduced motion is asked for).
- The homepage workbench implements the full ARIA tabs pattern (roving
  `tabindex`, Arrow/Home/End), and the flashcard deck answers Enter and Space.
- The floating assistant is a real dialog: it reports `aria-expanded`, closes
  on Escape and returns focus.
- The one `onclick=` left in a template is a print button.

## 10. Student-success measurement — NEW

**Was:** the audit asked where students give up. The platform ships no
tracker and no cookies, which is the right default, but it also meant nobody
could tell which pages were working.

**Now:** a deliberately narrow measurement that can never identify a visitor.

- `content_feedback` — one row per "was this page useful?" vote: the route
  (query string dropped), a verdict, an optional note, and a day bucket. No
  user id, no IP, no user agent, no cookie, no session.
- `page_stats` — a per-route, per-day count of visits. An aggregate, not a
  log.
- A small widget on topic, subject and problem pages, labelled as anonymous
  *before* the student clicks.
- An admin panel for staff with `analytics.view`, showing traffic joined with
  usefulness, the routes students rated down (at least two votes each), and
  what they wrote.
- `ENGINEVERSE_PAGE_STATS=off` turns the counter off; the usefulness button
  keeps working either way.
- A vote is capped at 20 an hour per browser. The cap lives only in the
  process's memory and its key is a hash of the caller's session subject - the
  account session when signed in, the random CSRF cookie otherwise. No IP
  address is read, and nothing about the caller is written down.

- `backend/engineverse/feedback.py` (new), `backend/web/api.py`,
  `backend/web/deps.py`, `backend/templates/_useful.html` (new),
  `backend/static/js/useful.js` (new), `backend/templates/admin.html`,
  `db/schema.sql` (and the generated `db/postgres/schema.pg.sql`).

## 11. Three defects the fixes uncovered

### 11.1 A test was leaking the old product name into every later page

`backend/tests/test_security.py` wrote `site_name = "EngineVerse"` to the
shared `site_config` table to exercise the white-label form, and never put it
back. The database is shared by the whole test session, so every page
rendered after that test called the product "EngineVerse" - which is how a
product called Meridian ends up publishing the old name, and why a brand
regression test could fail only in a full run.

Both tests that write branding now restore it in a `finally` block.

### 11.2 The traffic counter was an ambiguous upsert

The first version of the counter read `SET views = views + 1`. SQLite picks
the stored row silently; PostgreSQL reads the unqualified name as ambiguous
and raises `AmbiguousColumn`, so the counter would have failed on the first
write in production. The existing guard in `test_api_and_schema.py` caught it.
The right-hand side is now qualified with the table name.

### 11.3 The recovery link pointed at a route that does not exist

The "what to do next" panel added for wrong answers (§9.3) linked to
`/question-bank?topic=<slug>`. The route is called `/practice/questions`;
nothing answers `/question-bank`, so the button was a dead end - the one
thing the panel exists to prevent. The link now uses the real route, and
`test_api_and_schema.py::TestNoDeadLinks` (which walks every internal URL in
the templates) is what caught it.

## Still open, and why

These are named in the audit and are **not** fixed here. Saying so is part of
the point: the audit asked for confirmed defects to be separated from risks
that were never tested, and a list of things that are still untested is more
useful than a silence.

- **Platform parity matrix** (the audit's item on iOS/macOS/Android versus
  web). Not started; the native apps share the exported content bundle but
  the feature matrix does not exist as a document or a test.
- **Real-device responsive testing** and **measured performance on a mid-range
  phone**. Still unmeasured. The code has reduced-motion and keyboard paths,
  but nobody has run the site on real hardware and written down what they
  found.
- **Cross-device progress sync for the static copy.** The backup file is the
  honest answer for a copy with no server, and it is now a first-class flow;
  it is not a sync, and it is not presented as one.
- **Independent distribution and notarisation.** Out of scope for a code
  change; it is a release-process task.
- **Accreditation and certificate value.** Not a defect in the platform; it is
  an institutional fact the site must not overstate.
- **Question coverage is very uneven.** This is a **content** gap and it is
  measured, not hidden: Programming Fundamentals carries 96 questions while
  the median subject carries 4 (every published subject has at least 4, so no
  topic leads a learner to an empty page). `scripts/coverage_report.py` now
  names the heavy and thin subjects in the coverage report. Closing it means
  authoring questions, which is not a code change, and this round did not
  pretend otherwise.
- **Community and leaderboard need shared data.** These work only on a
  deployment with real users; nothing in the code can manufacture that.
